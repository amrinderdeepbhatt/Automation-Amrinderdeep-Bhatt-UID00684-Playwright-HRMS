Automation with Python + Playwright
 Project: HRMS
Phase 1: Framework Architecture & Core UI Automation
Theme: Design and implement a scalable UI automation framework using Python and Playwright.

 Goals:
Establish a clean, modular automation framework
Implement reusable browser interaction abstractions
Enable configurable, CLI-driven test execution

 Key Tasks:
[ ] Implement a scalable base setup for an industry grade level automation testing framework with appropriate dependency management tool and python project config files.
[ ] Design a modular folder structure (tests/, pages/,  utils/, config/ …) to support:
- Test scenarios
- Page abstractions
- Utilities
- Configuration management
[ ] Implement a common base abstraction (BasePage) for all pages with appropriate retry logic and smart waiters
[ ] Implement structured logging: (rotating file logs, timestamps, log levels)
[ ] Implement a CLI-based test runner using argparse to support runtime arguments such as environment, browser, and headless mode
[ ] Externalize environment and browser configuration using YAML files and read those configs from .yaml
[ ] Capture failure artifacts: Screenshots on test failure, Store artifacts in a dedicated directory


 Deliverables:
Modular Playwright automation framework
CLI-driven test execution
Centralized logging and failure artifact generation

Skills:
Python: classes, decorators, logging, error handling
Playwright: browser contexts, locators, assertions
Test architecture: abstraction, configuration, reusability

Phase 2: BDD, Data-Driven Testing & UI–API Validation
Theme: Build scenario-based, data-driven tests with UI and API validation.

 Goals:
Express test intent using business-readable scenarios
Separate test logic from test data
Validate UI workflows against backend APIs

 Key Tasks:
[ ] Introduce BDD using pytest-bdd:
- Feature files
- Shared and test specific step definitions
- Scenario outlines
[ ] Implement dynamic scenario generation using:
- YAML / CSV as data sources
- Jinja2 templates for feature generation
[ ] Integrate API validation using requests
[ ] Compare data between UI workflows and API responses
[ ] Implement retry-decorator with screenshot & HTML source dump
[ ] Add feature tags (@smoke, @regression) and control execution with CLI
[ ] Build test data layer with Faker, seeded randomness
Authentication Scenarios:
TC01: Verify user can successfully login to the application using a valid username and password.
TC02: Verify the system displays an appropriate error message when attempting login with invalid credentials.

Leave Management Scenarios
TC03: Verify a user can successfully submit a leave request with valid date ranges and required fields.
TC04: Verify the system prevents leave submission when using invalid dates (e.g., past dates, end date before start date, or insufficient balance)..
TC05: Verify the recently applied leave appears with the correct status in the "My Leave" section.

Filter & Action Scenarios
TC06: Verify the Leave Filter displays correct results when searching by specific keywords or Employee names.
TC07: Verify the From-To Date filter accurately narrows down the leave records within the selected timeframe.
TC08: Verify the leave records can be filtered correctly by Leave Status (Pending, Approved, Rejected) and Applied On date.
TC09: Verify a user can cancel a pending leave request and that the status updates immediately in the dashboard.

HR Scenarios
TC10: Verify an user can successfully locate a specific employee record by searching via Employee UID in the HR section.


 Deliverables:
Scenario-based BDD test suite
Data-driven test execution
UI-to-API validation implementation

 Skills:
Pytest-BDD: feature files, shared steps, tagging
Python: requests, generators, decorators, YAML, Jinja2
Test strategy: data abstraction, logic reuse, cross-layer validation
